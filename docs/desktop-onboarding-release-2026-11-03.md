# Desktop onboarding frontend release — 2026-11-03

Scope: hypitoken user-facing frontend only. Default Use token to Codex Desktop and native Windows. Keep CLI/WSL instructions in the separate terminal guide. Show https://ccswitch.io/ immediately, allow editing the primary model, and repair token-page links to /app/tokens.

CC Switch protocol baseline: QuantumNous/new-api main ba5f7367797566175a6cd97a748d430af3602a01, web/src/features/keys/components/dialogs/cc-switch-dialog.tsx. Import query fields and serialization order match: resource, app, name, endpoint, apiKey, nonempty model fields, homepage, enabled. No custom icon or inline config. Codex endpoint ends in /v1; Claude uses the gateway root. Provider name, gateway origin, user credential and selected model are deployment-specific values. The user requested Codex as the default even though New API's dialog defaults to Claude.

Validation: TypeScript/Vite production build passed. Ten onboarding tests passed. An additional comparison executed New API's current builder and this builder with identical fake inputs; Codex and Claude generated byte-identical URLs. Chrome DevTools confirmed the selected Codex tab, immediately visible CC Switch URL, editable model, collapsed CLI instructions and rendered native-Windows desktop guide. No real credential or live inference probe was used; opening the desktop CC Switch application itself was not tested on this Linux host.

Deployment method: standalone immutable frontend files behind Caddy; no Go rebuild, no application restart, no database migration. Only listed GET/HEAD SPA pages and existing static files are served from /srv/hypitoken-frontend/current. All API routes retain the existing upstream configuration. Missing assets fall back to the existing backend, preserving older cached frontend sessions. ops/frontend.caddy records the added site-local routes. Caddy config is validated before graceful reload; the old Caddyfile and frontend symlink are retained for rollback.

This release excludes the working tree's unpublished retry, balance-monitor, status-page and merchant-error backend changes. It does not deploy the separately prepared fixed-merchant fault repair.

The import action is a real `ccswitch://` anchor (not a JavaScript-only button), with a visible read-only URL and copy action before the first click. This preserves browser user activation and provides an explicit fallback when the desktop protocol handler is absent or blocked. The URL contains the user token and must not be shared.
